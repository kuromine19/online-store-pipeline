How the pipeline works

One Airflow DAG, store_dwh_daily, runs every night. Each table is a task group that extracts and cleans its source file into staging, then upserts it into the core schema. Tables load in waves so that facts never arrive before the dimensions they reference.

  • Safe to rerun. Every load is an upsert, so reprocessing a day never creates duplicates.
  • Bad rows are kept, not lost. Rejected rows go to audit.rejected_rows with the reason.
  • Checks with consequences. Blocking checks stop the run before reports are rebuilt; warnings are recorded.
  • Tested. Cleaning rules have unit tests, and CI runs the whole pipeline against a real PostgreSQL on every push.
All data on this page is synthetic.
